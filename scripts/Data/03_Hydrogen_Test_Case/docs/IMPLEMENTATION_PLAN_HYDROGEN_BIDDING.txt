HYDROGEN BIDDING TEST CASE — PHASED IMPLEMENTATION PLAN
========================================================

Document purpose
----------------
This document is the working implementation roadmap for extending the current hydrogen MILP test case from a schedule-and-settle dispatch model into a Badarinath-inspired, but simplified, day-ahead hourly bidding and clearing test case.

It is meant to be kept in the project sources, revisited after each Codex implementation step, and updated when design decisions change.

The plan deliberately splits the implementation into small phases. Do not ask Codex to implement all phases at once. The main risk is not coding speed; the main risk is creating a complex optimisation stack that produces results before we understand whether the bidding, clearing, settlement, physical feasibility, and reporting logic are actually correct.

Active scope
------------
Current focus:
- Green hydrogen test case.
- Day-ahead only.
- Hourly first.
- Fixed bid-price grid with optimised bid quantities.
- Price-taking clearing against realised historical DA prices.
- Deterministic redispatch after actual clearing.
- Risk-neutral and CVaR variants.
- Comparison of scenario inputs later: XGBoost FS3, LEAR FS3, LEAR Strict.
- Later comparison of hourly vs quarter-hour and D-only vs D+4 where tractable.

Explicitly out of scope for now:
- Exclusive group bids.
- Full EUPHEMIA clearing.
- Price-maker behaviour.
- mFRR capacity or activation.
- Full steel-plant MILP.
- Endogenous bid-price optimisation.

Core methodological distinction
-------------------------------
The existing hydrogen model is useful, but it is not yet a true bidding model.

Current schedule-and-settle logic:
- The optimiser chooses a dispatch schedule.
- Scenario prices influence expected cost and CVaR.
- In realised evaluation, electricity is assumed available and settled against realised prices.
- Forecast errors mainly affect realised cost.

Target bidding-clearing logic:
- The optimiser submits demand bid quantities at fixed bid-price levels.
- A bid block clears only if bid_price >= market_price.
- Under scenarios, scenario prices determine scenario-specific clearing.
- After optimisation, submitted bids are cleared against realised historical prices.
- Only cleared electricity is available for deterministic redispatch.
- Forecast/scenario errors can affect both realised cost and physical procurement.

This distinction is crucial for the thesis because it tests whether better scenarios lead to better economic and operational outcomes, not only better predicted prices.

PHASE 1 — Add bidding and clearing primitives only
==================================================

Goal
----
Create the data structures and pure functions needed for hourly bid curves and market clearing, without changing the optimisation model yet.

Why this phase matters
----------------------
This isolates the market-clearing logic from the MILP. If clearing is wrong, the optimiser results will be meaningless. This phase should be testable with tiny toy examples.

---------------

Possible files to update
------------------------

Core concepts
-------------
Use a fixed bid-price grid. Example default:

[-500, -100, 0, 50, 100, 125, 144, 158, 175, 200, 250, 500, 1000, 3000]

Interpretation:
- low bid prices clear only in very cheap hours;
- 144 EUR/MWh is approximate electricity value of hydrogen revenue at 8 EUR/kg and 18 kg/MWh;
- 158 EUR/MWh is the earlier reference/opportunity-cost threshold;
- high bid prices protect supply but expose the plant to expensive clearing.

Bid curve schema
----------------
Each submitted bid row should contain:
- run_id
- strategy
- forecast_model or scenario_model
- granularity
- horizon
- forecast_origin_utc
- delivery_start_utc
- bid_block
- bid_price_eur_per_mwh
- bid_quantity_mw
- timestep_hours

Actual clearing output schema
-----------------------------
Each cleared bid row should contain:
- all bid curve columns;
- actual_price_eur_per_mwh;
- accepted;
- cleared_quantity_mw;
- cleared_energy_mwh.

Acceptance rule
---------------
For demand bids:

accepted = bid_price_eur_per_mwh >= actual_price_eur_per_mwh

If accepted:

cleared_quantity_mw = bid_quantity_mw

If rejected:

cleared_quantity_mw = 0

----
Convert existing dispatch schedules into simple bids and clear them against realised prices. This is a bridge for debugging and interpretation, not the final bidding optimiser.

Why this phase matters
----------------------
It helps answer a simple but powerful question: if the current schedule had been submitted as actual DA demand bids, how much of it would have cleared?

This phase makes the difference between scheduling and bidding visible to a human reader.

Bridge strategies
-----------------
For a dispatch schedule with total load:

load_t = electrolyser_power_t + compressor_power_t

Create at least two simple bid variants:

1. Reference-price one-block bid
   - quantity = load_t
   - bid_price = 158 EUR/MWh

2. High-price one-block bid
   - quantity = load_t

Optional later:

Reference-price bid:
- shows whether the schedule is economically willing to consume at realised prices;

PHASE 3 — Add deterministic redispatch after actual clearing
============================================================

Goal
----
Given an actually cleared electricity profile, solve the physical hydrogen operation model using only that available electricity.

Why this phase matters
----------------------
This is the bridge from market outcome to physical feasibility. Bids do not directly equal production. After clearing, the plant must redispatch within its physical constraints.

This phase should be implemented before the full stochastic bidding optimiser, because it isolates the post-clearing physical feasibility problem.

Files to create or update
-------------------------
- hydrogen/redispatch.py
- tests/test_redispatch.py
- hydrogen/metrics.py or hydrogen/bidding_metrics.py
- hydrogen/plotting_bidding.py
- notebooks/05_bidding_clearing_debug.ipynb or new 06 redispatch section

Redispatch input
----------------
For each hour t:
- delivery_start_utc
- cleared_energy_mwh
- actual_price_eur_per_mwh
- initial hydrogen inventory
- plant parameters

Redispatch variables
--------------------
For each hour t:
- electrolyser_power_mw
- electrolyser_on binary if used
- compressor_power_mw
- hydrogen_produced_kg
- hydrogen_compressed_or_sold_kg
- hydrogen_storage_kg
- unused_cleared_energy_mwh
- shortfall_kg for the day

Core equality
-------------
Use:

used_energy_mwh_t + unused_cleared_energy_mwh_t = cleared_energy_mwh_t

where:

used_energy_mwh_t = timestep_hours * (electrolyser_power_mw_t + compressor_power_mw_t)

This is preferred over used_energy <= cleared_energy because it explicitly accounts for over-procurement.

6. Save redispatch time series and metrics.
7. Add toy tests:
   - zero cleared energy should force no electricity use and likely shortfall;
   - abundant cleared energy should allow production but may create unused energy if too much clears;
   - storage reserve should not be violated.

-----------------
Check:
- used + unused = cleared energy for every hour;
- electrolyser and compressor power respect bounds;
- hydrogen balance closes;
- storage remains within bounds;
- shortfall is reported if target cannot be met;
- unused energy is reported if cleared energy cannot be consumed;
- realised DA settlement cost uses cleared energy, not used energy;

PHASE 4 — Build first true risk-neutral hourly bid optimiser
============================================================

Goal
----
Implement the first real stochastic hourly bidding model with fixed bid prices and optimised bid quantities.

Why this phase matters
----------------------
This is where the model becomes a true bidding test case. The first-stage decision is the bid curve. Scenario-specific prices determine scenario-specific clearing, and scenario-dependent physical operation follows after clearing.

Important modelling choice
--------------------------
Do not optimise bid prices yet.
Use fixed bid prices and optimise quantities.

This keeps acceptance as a parameter:

acceptance_{s,t,b} = 1 if bid_price_b >= scenario_price_{s,t}, else 0

Decision variable:

q_{t,b} >= 0

Scenario-cleared energy:

E_DA_{s,t} = timestep_hours * sum_b acceptance_{s,t,b} * q_{t,b}

This formulation stays linear.

Files to create or update
-------------------------
- hydrogen/bidding_model.py
- hydrogen/bidding_metrics.py
- hydrogen/model_stats.py if not present
- tests/test_bidding_model_small.py
- notebooks/06_hourly_bid_model_single_day.ipynb

Core variables
--------------
First-stage variables:
- q_{t,b}: submitted bid quantity in MW for hour t and bid block b.

Scenario-dependent recourse variables:
- electrolyser_power_{s,t}
- electrolyser_on_{s,t} if binary is retained
- compressor_power_{s,t}
- hydrogen_produced_{s,t}
- hydrogen_compressed_or_sold_{s,t}
- hydrogen_storage_{s,t}
- unused_cleared_energy_{s,t}
- shortfall_{s,d}

Core constraints
----------------
1. Bid capacity:

sum_b q_{t,b} <= P_el_max + P_comp_max

2. Scenario clearing:

E_DA_{s,t} = timestep_hours * sum_b acceptance_{s,t,b} * q_{t,b}

3. Scenario electricity balance:

used_energy_{s,t} + unused_energy_{s,t} = E_DA_{s,t}

4. Physical constraints:
- electrolyser bounds;
- ramping;
- hydrogen production;
- compressor bounds;
- compressor conversion;
- storage balance;
- storage bounds;
- daily target/shortfall.

Objective
---------
Risk-neutral objective:

minimise expected scenario net cost

where scenario net cost includes:
- DA procurement cost based on scenario-cleared energy;
- unused energy penalty if used;
- shortfall penalty;
- minus hydrogen revenue;
- minus terminal inventory value correction.

3. Solve one-day with a tiny scenario set first, e.g. 3 scenarios.

6. Save scenario_recourse_timeseries.parquet.
7. Save model stats and solver log.
8. Add validation checks.

PHASE 7 — Add CVaR to the hourly bid optimiser
==============================================

CVaR formulation
----------------
For scenario net cost C_s:

Variables:
- zeta = VaR threshold;
- xi_s >= 0 = excess loss above zeta.

Constraints:

xi_s >= C_s - zeta
xi_s >= 0

CVaR:

CVaR_alpha = zeta + (1 / (1 - alpha)) * sum_s probability_s * xi_s

Objective:

minimise expected_cost + gamma * CVaR_alpha

Default:
- alpha = 0.95
- gamma grid = [0, 0.005, 0.01, 0.025, 0.05, 0.10, 0.20, 0.50]

Important rule
--------------
Do not select gamma based on final test performance.

Use validation-like weeks for parameter selection. Test-period gamma sweeps may be shown only as ex-post sensitivity, not as tuned model choice.

Implementation tasks

5. Run selected-week CVaR sensitivity on validation-like period.
6. Add risk-return reporting.

Minimum metric definitions to keep consistent
=============================================

Economic metrics
----------------
1. Realised DA settlement cost
   Unit: EUR
   Definition: sum_t actual_price_t * actual_cleared_energy_t.
   Why it matters: measures what the plant actually pays for DA electricity.

2. Hydrogen revenue
   Unit: EUR
   Definition: hydrogen_sold_kg * hydrogen_price_eur_per_kg.
   Why it matters: connects production to economic value.

3. Adjusted profit
   Unit: EUR
   Definition: revenue - DA settlement cost - penalties + terminal inventory correction.
   Why it matters: prevents artificial profit from depleting storage.

4. Uplift vs price-insensitive
   Unit: EUR or %
   Definition: strategy_profit - price_insensitive_profit.
   Why it matters: shows value of optimisation relative to naive operation.

5. Value captured vs perfect foresight
   Unit: %
   Suggested definition: (strategy_profit - price_insensitive_profit) / (perfect_foresight_profit - price_insensitive_profit).
   Why it matters: shows how much of the oracle value is captured.

Risk metrics
------------
1. Scenario expected cost/profit
   Optimisation-time probability-weighted scenario result.

2. VaR
   Threshold for high-cost tail.

3. CVaR
   Expected cost in the worst tail beyond VaR.

4. Worst-scenario cost/profit
   Most adverse scenario in the optimisation set.

5. Realised downside metric
   Empirical downside over days/weeks, e.g. worst-day profit or lower-tail average.

Reliability metrics
-------------------
1. Target fulfilment
   hydrogen_sold_or_compressed / target.

2. Shortfall
   unmet target in kg.

3. Reserve violations
   should normally be zero if hard-constrained.

4. Storage boundary hits
   number of periods at min/max storage.

5. Infeasible days
   count and list of days where solver failed or model infeasible.

Bidding metrics
---------------
1. Submitted energy
   Energy offered through bids.

2. Cleared energy
   Energy accepted after market clearing.

3. Used energy
   Energy physically consumed by plant.

4. Rejected energy
   Submitted energy that did not clear.

5. Unused cleared energy
   Cleared energy that could not be physically consumed.

6. Clearing ratio
   cleared energy / submitted energy.

7. Hours with zero clearing
   hours where no submitted demand cleared.

8. Actual price above highest bid
   warning metric for total rejection risk.

Operational metrics
-------------------
1. Electrolyser load profile.
2. Compressor load profile.
3. Hydrogen production.
4. Hydrogen sold/compressed.
5. Storage trajectory.
6. Ramping behaviour.
7. Starts/stops if binary on/off is used.
8. Price responsiveness, e.g. correlation between price and load.

Computational metrics
---------------------
1. Solve time.
2. Solver status.
3. Objective value.
4. MIP gap.
5. Number of variables.
6. Number of binary variables.
7. Number of constraints.
8. Scenario count.
9. Horizon length.

Common red flags
================

Stop and investigate if any of these occur:

1. Profit improves while hydrogen production or target fulfilment collapses.
2. Storage is depleted to create profit without terminal correction.
3. The model buys electricity that did not clear.
4. Settlement cost is based on used energy instead of cleared energy.
5. Scenario probabilities are missing or ignored.
6. Bid quantities differ by scenario before uncertainty is revealed.
7. Actual prices are used inside bid optimisation.
8. Failed or infeasible days are silently removed.
9. Hourly and quarter-hour cases are compared while changing other assumptions.
10. Scenario undercoverage is ignored when interpreting CVaR.
11. Perfect foresight is described as realistic rather than an oracle upper bound.
12. Plots show only profit and not production, storage, clearing, or shortfall.
