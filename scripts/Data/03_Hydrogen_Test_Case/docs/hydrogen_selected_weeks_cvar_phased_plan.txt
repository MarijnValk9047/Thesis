HYDROGEN MILP — COMMON-SUPPORT SELECTED-WEEK AND CVaR IMPLEMENTATION PLAN
=======================================================================

Document purpose
----------------
This plan defines the next implementation sequence for the hydrogen stochastic bidding test case now that all three hourly model scenario artifacts are valid, but LEAR Strict is only available on partial test-year support.

The goal is to move from validated scenario artifacts to a defensible three-model comparison of hourly D-only stochastic bidding performance, followed by a controlled CVaR extension. The plan prioritises common support, traceable selected weeks, reporting discipline, and avoidance of test-set tuning.

Important methodological rules
------------------------------
1. Do not compare models on different weeks.
2. Do not silently use different delivery support per model.
3. Do not tune CVaR gamma on the final test weeks.
4. Validation weeks may be used for CVaR gamma selection or narrowing.
5. Test weeks may be used for final selected-week reporting and ex-post sensitivity only.
6. Keep hourly and quarter-hour tracks separate.
7. Do not add mFRR, quarter-hour, D+4, or exclusive group bids in this sequence.
8. Default model scope is hourly D-only DA-only stochastic hourly bidding with pay-as-cleared settlement and deterministic redispatch.

Target comparison structure
---------------------------
The selected-week framework should produce two linked but separate experiment layers:

A. Validation-layer CVaR analysis
   Purpose:
     choose or narrow CVaR gamma settings without using test performance.
   Period:
     common validation support across all three models.
   Output:
     risk-return frontier and recommended gamma policy.

B. Test-layer selected-week model comparison
   Purpose:
     compare scenario/model inputs on diagnostic market regimes.
   Period:
     common test support across all three models.
   Output:
     risk-neutral and fixed-risk-averse results by model and week.

PHASE 4 — Validation-week CVaR smoke/sweep
==========================================

Goal
----
Test risk-averse stochastic bidding on real scenarios without tuning on test data.

Scope
-----
Use validation weeks only.
Start with one validation stress week. Then optionally add a stable validation week.

Models
------
Start with all three models if computationally feasible. If not, start with LEAR Strict + one FS3 model, then extend to all three.

CVaR settings
-------------
Default alpha:
  0.95

Initial gamma grid:
  [0, 0.01, 0.05, 0.10, 0.25, 0.50]

If runtime is high, reduce to:
  [0, 0.05, 0.25]

Required outputs
----------------
- cvar_sweep_daily.csv
- cvar_sweep_weekly.csv
- cvar_frontier_by_model.csv
- cvar_bid_firmness_metrics.csv
- cvar_validation_checks.csv
- model_stats_by_gamma.csv
- README_cvar_validation_sweep.md

Required metrics
----------------
Economic:
- expected adjusted profit;
- realised adjusted profit;
- benchmark profit;
- stochastic-minus-benchmark;
- DA settlement cost;
- hydrogen revenue.

Risk:
- VaR threshold;
- CVaR loss;
- worst-scenario profit;
- downside tail mean;
- expected-vs-realised profit delta;
- realised outcome percentile within scenario distribution if feasible.

Bidding:
- submitted energy;
- cleared energy;
- rejected energy;
- clearing ratio;
- weighted average bid price;
- share of energy at high bid tiers;
- share at market cap;
- bid headroom over actual price for accepted blocks.

Physical:
- hydrogen sold;
- shortfall;
- unused cleared energy;
- storage min/max;
- reserve boundary hits;
- terminal inventory change.

Required plots
--------------
1. Risk-return frontier: realised/expected profit vs CVaR loss.
2. Gamma vs worst-scenario profit.
3. Gamma vs clearing ratio/rejected energy.
4. Gamma vs hydrogen sold/shortfall.
5. Gamma vs high-bid share and average bid price.
6. Scenario profit distribution by gamma.

Gamma selection rule
--------------------
Do not select gamma on test-week profit.
Use validation results to define either:
- one preferred gamma; or
- a small fixed set of gamma values for test reporting, e.g. gamma=0 and gamma=0.10/0.25.

Acceptance criteria
-------------------
- CVaR runs solve for selected validation week(s).
- CVaR loss reconstruction validates.
- Gamma changes are interpretable or explicitly reported as weak/no effect.
- No test-period tuning occurs.

PHASE 8 — Quarter-hour tracks remain separate
=============================================

Goal
----
Prevent accidental mixing of hourly selected-week results with quarter-hour observed or counterfactual tracks.

Rules
-----
1. Quarter-hour observed-market track uses observed targets only and later 2026 support.
2. Quarter-hour counterfactual track uses synthetic/frozen paths and must be labelled counterfactual.
3. Hourly vs quarter-hour comparison is blocked unless support and assumptions are matched or differences are explicitly framed.
4. Do not use quarter-hour observed 2026 results to fill hourly 2024/2025 gaps.

Acceptance criteria
-------------------
- Reporting clearly separates hourly, QH observed, and QH counterfactual.
- No mixed-support plot is presented as a clean granularity comparison.
